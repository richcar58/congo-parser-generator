# SQL Expression Parser (Rust)

A SQL expression parser generated by [CongoCC](https://congocc.org) from the `SqlExpr.ccc` grammar. This example demonstrates CongoCC's Rust code generation with a richer grammar than the arithmetic example, including boolean logic, comparisons, LIKE, IN, BETWEEN, IS NULL, case-insensitive keywords, and a full lexer with string literals.

## Grammar

The grammar defines ten productions for SQL filter expressions:

| Production | Pattern | Description |
|---|---|---|
| `SqlExpression` | ROOT | Top-level entry point; parses `OrExpression <EOF>` |
| `OrExpression` | SEPARATOR | `AndExpression (<OR> AndExpression)*` |
| `AndExpression` | SEPARATOR | `NotExpression (<AND> NotExpression)*` |
| `NotExpression` | PREFIX | `<NOT> NotExpression \| ComparisonExpression` |
| `ComparisonExpression` | OPTIONAL_SUFFIX | `AdditiveExpression (comparison \| LIKE \| IN \| BETWEEN \| IS NULL)?` |
| `ValueList` | SEPARATOR | `AdditiveExpression ("," AdditiveExpression)*` |
| `AdditiveExpression` | INFIX | `MultiplicativeExpression ((+ \| -) MultiplicativeExpression)*` |
| `MultiplicativeExpression` | INFIX | `UnaryExpression ((* \| /) UnaryExpression)*` |
| `UnaryExpression` | PREFIX | `<MINUS> UnaryExpression \| PrimaryExpression` |
| `PrimaryExpression` | CHOICE | `<INTEGER_LITERAL> \| <DECIMAL_LITERAL> \| <STRING_LITERAL> \| <TRUE> \| <FALSE> \| <NULL> \| <IDENTIFIER> \| "(" OrExpression ")"` |

Keywords (`AND`, `OR`, `NOT`, `TRUE`, `FALSE`, `NULL`, `LIKE`, `IN`, `BETWEEN`, `IS`) are case-insensitive.

## Generated Files

All Rust source files are fully generated by CongoCC and should not be edited by hand:

| File | Description |
|---|---|
| `lib.rs` | Crate root; re-exports public API and typed operator enums |
| `arena.rs` | Arena allocator, `AstNode` enum, typed operator enums, pretty-print |
| `tokens.rs` | `Token` struct and `TokenType` enum |
| `lexer.rs` | Lexical analyzer (keywords, operators, integers, decimals, strings, identifiers) |
| `parser.rs` | Recursive descent parser |
| `visitor.rs` | Depth-first AST visitor with `VisitControl` |
| `error.rs` | `ParseError` with line/column location tracking |

To regenerate from the grammar:

```bash
# From the repository root
ant clean jar
java -jar congocc.jar -lang rust -d examples/rust-test/sqlexpr examples/rust-test/sqlexpr/SqlExpr.ccc
```

## Usage

```rust
use sqlexpr::*;

fn main() -> Result<(), ParseError> {
    let input = "age >= 18 AND status IN ('active', 'pending')".to_string();
    let mut parser = Parser::new(input)?;
    let root = parser.parse()?;
    println!("{}", parser.arena().pretty_print(root, 0, parser.input()));
    Ok(())
}
```

## Visitor Pattern

The generated `visitor.rs` provides `Arena::visit()` for depth-first AST traversal:

```rust
pub fn visit<F>(&self, root: NodeId, f: &mut F, options: Option<&dyn Any>) -> VisitControl
where
    F: FnMut(NodeId, &AstNode, &Arena, usize, Option<&dyn Any>) -> VisitControl,
```

The callback receives `(node_id, node, arena, depth, options)` at each node and returns a `VisitControl`:

- `Continue` -- visit children, then continue with siblings
- `SkipChildren` -- skip this node's children, continue with siblings
- `Stop` -- halt traversal entirely

The `options` parameter passes caller state into the callback as `&dyn Any`. Since this is a shared reference, use `Cell` or `RefCell` for interior mutability when the visitor needs to accumulate results.

### Example: Counting Nodes

```rust
use std::cell::Cell;
use std::any::Any;
use sqlexpr::*;

struct VisitorState {
    count: Cell<usize>,
}

fn count_node(
    _id: NodeId, node: &AstNode, _arena: &Arena,
    depth: usize, options: Option<&dyn Any>,
) -> VisitControl {
    let state = options.unwrap().downcast_ref::<VisitorState>().unwrap();
    let n = state.count.get() + 1;
    state.count.set(n);
    let indent = "  ".repeat(depth);
    println!("{}Node {}: depth={}, type={:?}", indent, n, depth, node);
    VisitControl::Continue
}

let input = "a = 1 AND b < 2 OR c > 3".to_string();
let mut parser = Parser::new(input).unwrap();
let root = parser.parse().unwrap();

let state = VisitorState { count: Cell::new(0) };
parser.arena().visit(root, &mut count_node, Some(&state));
assert!(state.count.get() > 0);
```

See `tests/visitors/sqlexpr_visitor.rs` for the full implementation with diagnostic output.

## Serde Support

The generated parser includes optional [serde](https://serde.rs) support behind a feature flag. When enabled, all AST node types, operator enums, token types, and error types derive `Serialize` and `Deserialize`.

To build with serde support:

```bash
cargo build --features serde
```

To run tests with serde enabled:

```bash
cargo test --features serde
```

To use serde in a dependent crate, enable the feature in your `Cargo.toml`:

```toml
[dependencies]
sqlexpr = { path = "../sqlexpr", features = ["serde"] }
```

## Running Tests

All tests use `cargo test` from the `examples/rust-test/sqlexpr/` directory.

```bash
# Run all tests (65 integration + 1 visitor)
cargo test

# Run all tests with printed output visible
cargo test -- --nocapture

# Run only the integration tests
cargo test --test integration_tests

# Run only the visitor test
cargo test --test visitor_test

# Run visitor test with output visible
cargo test --test visitor_test -- --nocapture

# Run a single test by name
cargo test test_simple_equality

# Run tests matching a pattern
cargo test test_pretty_print
```
